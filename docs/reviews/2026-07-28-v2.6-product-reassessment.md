# YA FundMind OS v2.6 产品重新评审

评审日期：2026-07-28

## 结论

v2.6 已经是一个可持续运行的本地基金研究系统，但还不是面向普通用户的完整基金信息平台。

当前优势集中在工程底座：daily/weekly 自动运行、AKShare 全市场基金目录、基金历史净值、主要指数和行业板块曲线、SQLite 缓存、provider trace、结构化 contract、基金详情、组合、证据、报告和本地 Web 均已存在。当前不足集中在产品表面：基金档案字段覆盖不完整、ETF 行情字段没有形成独立工作区、用户页面暴露工程诊断、组合缺失估值时产生误导性数值、新闻仍是 fixture。

因此下一步不应继续给“研究报告页”叠加模块，也不应进入交易系统。推荐把下一大版本定位为 **V3 Fund Information Platform**：

- 第一层解决“找得到、看得全、看得懂、知道数据日期”。
- 第二层保留自选、组合和研究证据。
- Research Copilot、审核、报告和系统诊断降为二级工作区。
- 不自动推荐、不执行交易、不接券商、不承诺收益。

## 关键发现

### P0

当前未发现阻断 daily、Web、测试或数据产物生成的 P0。

### P1：进入 V3 前必须解决

1. **产品定位与信息架构错位**

   主导航和页面文案仍以 Research Desk、报告、证据和工程状态为中心。用户真正的高频路径应是“市场 -> 基金库 -> 基金详情 -> 自选/组合”。

2. **基金档案数据覆盖不足**

   当前 `FundDetail` 模型只有少数字段，且 AKShare 的 `fund_overview_em`、`fund_fee_em`、`fund_portfolio_hold_em`、`fund_rating_all`、`fund_manager_em` 等尚未接入。现有详情页大量显示空值。

3. **缺失值被误解释为真实 0**

   `fund_agent/providers.py` 中收益字段使用 `value or 0.0`；缺失值可能被转换成 0。组合估值不可用时，当前 API 输出 `current_value=0.0`、`unrealized_return_pct=-100.0`。这会把“未知”误导为“实际归零”。V3 应新增 optional domain/product mapper，并通过 legacy adapter 和 snapshot regression 保持现有主 score/risk 不变。

4. **工程诊断暴露在用户主表面**

   `cache:akshare`、`warning`、`partial`、`unknown`、`missing_position_valuation`、`nav_history_summary`、`fund_company` 等内部值直接出现在普通页面。用户层应显示中文解释；原始诊断保留在“数据状态”抽屉或系统页。

5. **ETF 行情与开放式基金净值没有形成两套展示语义**

   V3 先对 ETF 展示交易所行情、成交、IOPV 和折溢价；普通开放式基金主要展示净值、申购/赎回状态、确认日和费率。LOF 行情需要独立 endpoint 后再纳入，不能套用 ETF 模板。

6. **新闻页面不能作为正式功能发布**

   当前 `outputs/news/news_evidence_report.json` 是 fixture 示例，且包含 `example.com`。在接入真实来源前，正式产品应隐藏该入口或明确标为演示数据，不能让用户误认为是当天新闻。

7. **自选与持仓边界不清**

   watchlist 已更新为用户自选基金，但 portfolio 仍是示例组合。产品必须明确“自选观察”与“实际持仓”是不同数据集，并在空配置时给出诚实空态。

### P2：核心数据闭环后优化

- 高级图表、同类对比、收益区间选择和导出。
- 深浅主题与更细的视觉动效。
- 页面个性化布局、更多筛选器和快捷键。
- 公网部署、多用户、账号和云同步。
- 真实新闻/公告的多源核验。

## 采用决定

- 保留 v2.6 后端、contract、自动化和研究能力。
- V3 新增产品化 Fund Profile 和 ETF Quote 域模型，不用原始 provider 字段直接驱动 UI。
- 普通页面只展示可解释的用户字段；诊断字段保留但降级到系统页。
- 优先使用 AKShare 已有公募基金接口补齐数据，不先投入多源核验。
- 新闻/公告单独排期，不与基金核心资料接入混在同一 Milestone。
- 主评分、主风险和 Research Copilot 不作为 V3 首屏，不因 V3 自动改变结论。

## 对抗式评审收敛

规划草案完成独立对抗式评审，未发现 P0。发现的 11 项 P1 已在 V3 契约中收敛：

| P1 | 收敛决定 |
| --- | --- |
| missing/null 与 legacy score 冲突 | V3 optional domain + product `null`；legacy adapter + score/risk snapshot |
| “全部基金”范围不明 | 定义为三个 AKShare endpoint 的规范化并集并输出 coverage |
| 全量/按需 endpoint 冲突 | 全量 endpoint 按 TTL snapshot，单基金 endpoint 才按需 |
| 规模/费率/评级语义过平 | 保留单位、日期、条件、渠道、原/优惠费率和评级机构 |
| ETF/LOF 范围冲突 | V3 只承诺 ETF 行情；历史保存 `adjust`，LOF 后置 |
| AC-task 只做区间映射 | 33 条 AC 均映射到明确 task 和必须测试 |
| live smoke 可选 | 新 endpoint 对应版本发布前必须真实 smoke 成功 |
| M1 首页文件判断错误 | 根路由保持 `/market`，修改 `App.tsx` / `MarketPage.tsx` |
| API 中文状态矛盾 | API 返回稳定 code，可选 display message；Web 本地化 |
| 开源配置与用户配置冲突 | M5 设计 example/local 迁移，先备份且不删除现有配置 |
| 多文档状态漂移 | `tasks.md` 是唯一任务状态源，Roadmap/Plan 不维护完成状态 |
