# V3 M1 信息架构与只读自选页实施计划

## 目标

完成 V3 M1 的产品信息架构收口：用户打开本地 Product Web 后，能在一级导航中清楚地区分市场、全市场基金、自选和组合；研究、审核、系统和报告仍然可访问，但不抢占主要浏览任务。

本批次只复用既有 `GET /api/product/watchlist` 只读契约，把现有基金终端内嵌的自选视图提升为独立页面。它不修改 YAML、主评分、主风险、daily/weekly 或数据源。

## 已确认的设计契约

### 任务与信息模型

1. `行情总览`：看市场、指数、板块和主题。
2. `基金终端`：搜索全市场基金与 ETF，并进入详情。
3. `自选`：只展示现有 `configs/watchlist.yaml` 已生成的观察基金资料；不表示推荐，也不等同于持仓。
4. `组合`：只展示现有 portfolio 观察与估值可用性。
5. `研究工具` 与 `系统工具`：保留可直达页面，不进入一级数据终端。

### 布局与响应式

- 桌面左侧第一个导航分组仅四个一级工作区：行情总览、基金终端、自选、组合。
- `自选` 页使用指标带、筛选框和可进入基金详情的表格；没有编辑、删除、调仓或推荐按钮。
- 平板与手机沿用现有抽屉导航、焦点回归和 `inert` 逻辑；自选表格允许在容器内滚动，首要信息在窄屏保留。
- 页面继续使用 Market Ledger Design Lock：白色数据画布、深墨导航、翡翠强调，涨红跌绿。

## 范围与非目标

### 范围内

- `web/src/lib/routes.tsx` 的导航分层与 `/watchlist` 路由。
- `web/src/pages/WatchlistPage.tsx` 的只读自选浏览。
- 从 `FundsPage` 移除重复的内嵌自选 tab，保持全市场搜索职责单一。
- React 单元测试、Product Web 三视口与基础无障碍验证。
- 更新 V3 task/backlog 的实际进度。

### 范围外

- 不新增或修改 Product API、SQLite cache、provider、YAML 写入或定时任务。
- 不显示 provider、cache、trace、schema 或原始质量码。
- 不改主评分、主风险、研究主结论或任何买卖建议。
- 不新接新闻、交易、券商或外部网络调用。

## 执行批次

1. 先添加路由/页面失败测试，证明一级导航、根路由、只读自选入口和详情跳转。
2. 抽取或迁移既有自选展示，删除基金终端内的重复 tab，保留全市场 URL 查询行为。
3. 完成导航信息层级与窄屏样式检查。
4. 运行 Python/React 全量回归、构建、Playwright 1440/768/375 与 keyboard/focus 检查。
5. focused diff review、PR、CI、merge，并仅重启独立 local Product Web 服务。

## 验收与风险

| 验收 | 证据 |
| --- | --- |
| `AC-005` 一级导航为市场、基金、自选、组合 | 路由/壳层测试与实际截图 |
| `AC-006` 研究、报告、系统是二级工具 | 导航 DOM 测试 |
| `AC-007` 首页直接进入市场工作区 | 根路由测试 |
| `AC-023` 自选来源和持仓语义分离 | 自选页只读契约测试与页面文案 |
| 不引入内部诊断或写入能力 | DOM 断言、API 调用检查和 diff review |

风险是自选产物缺失或资料不全。页面只能显示中文空态或“资料待补充”，不能把缺失值替换为 0，也不能让用户误以为网页可以写入当前配置。若回归失败，可回滚本批次的单个 merge commit；既有 `/funds`、`/portfolio`、`/api/product/watchlist` 与 daily 输出不受影响。

## 实施结果

- 一级数据导航已收敛为“行情总览、基金终端、自选、组合”；研究与系统页面保留在次级分组。
- `/watchlist` 只读取既有 Product API，展示配置观察基金、资料覆盖和数据日期；基金终端不再混入自选 tab。
- 自选行可直接进入 `/funds/:code`，详情页会保留返回 `/watchlist` 的路径。
- 已完成 TypeScript、45 个前端测试、Python 全量回归、构建和 1440/768/375 三视口浏览器检查；浏览器控制台无 warning/error。
