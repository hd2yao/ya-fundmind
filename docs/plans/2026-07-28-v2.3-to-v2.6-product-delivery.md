# YA FundMind OS v2.3 至 v2.6 产品交付计划

## 背景和目标

现有本地 Product Web 已能读取结构化市场、基金、组合和证据产物，但基金详情停留在抽屉、组合和证据缺少跨页研究路径。后续交付的真实目标不是增加报告段落，而是让用户可以在本机完成一条可核对的数据浏览路径：市场或搜索结果 -> 基金详情与历史净值 -> 已配置组合的暴露与数据缺口 -> 相关新闻/公告证据。

本计划按四个可回滚版本执行：`v2.3.0` 发布收口、`v2.4.0` 基金数据终端、`v2.5.0` 组合工作台、`v2.6.0` 证据浏览器。每一版独立 PR、CI、测试、浏览器验收、tag 和本地 Product Web 部署。

## 范围

- 复用已有 AKShare/SQLite/JSON/FastAPI 数据路径，改善 Product Web 的数据浏览和跨页导航。
- 将基金详情提升为可链接的独立页面，保留全市场搜索和自选池的范围边界。
- 将组合的已配置持仓、暴露、估值缺口和观察性问题组织为可阅读、可跳转的工作台。
- 将既有新闻/公告 evidence 按质量、主题和关联基金组织为可核对的浏览器。
- 每一页显式展示来源、交易日、同步时间和 stale/fallback/质量状态；页面刷新只重新读取本地 API。

## 非目标

- 不新增或更换 provider，不做多源核验、新闻抓取或历史回填。
- 不改主评分、主风险、默认 provider、`configs/watchlist.yaml`、`configs/portfolio.yaml` 或 daily/weekly scheduler 时间。
- 不做 Web 公网部署、登录、券商接入、自动交易、买卖建议、收益承诺、LLM、MCP 或 LangGraph。
- 不解析 Markdown/HTML 作为业务数据；页面只读既有 JSON/API。

## 设计与执行契约

- 延续 [v2.3 Research Workbench Design Lock](../design/v2.3-research-workbench-design-lock.md)：深墨绿骨架、浅石墨画布、矿物青绿强调；数据带、表格和主图优先，不做营销 hero、渐变或卡片墙。
- 每个页面必须有 loading / empty / error / stale / fallback 状态；没有值时显示 `--` 或明确的缺口说明，不以 `0` 补全。
- 详情访问是对已索引基金的本地结构化 API 读取；本轮不在浏览器增加任何隐式 live provider 调用。
- 所有版本必须在 1440、768、375 宽度通过 Playwright 核验；默认 Python/Vitest 测试不依赖真实网络。
- 每个版本完成后做 focused diff 和对抗式审查；若涉及 API response、数据语义或范围变化，先更新本计划和相应类型/测试再实现。

## 版本批次与验收

### v2.3.0：Market Freshness & Research Workbench 发布

- 目标：将已合并的指数预热与市场研究台正式发布。
- 必做：统一 package/runtime 版本为 `2.3.0`，补 release report、CHANGELOG、README；全量 Python/Web/contract 验证；PR、CI、tag 和本地 Web 部署复核。
- 验收：市场页同时显示 `as_of` 和 `updated_at`；真实本地 cache 页面不会把非交易日误标为 stale；所有既有 `v2.3` 测试与浏览器验收可复核。
- 不做：不增页面功能、不改数据契约。

### v2.4.0：Fund Data Terminal & Detail

- 目标：让任意已索引基金拥有可分享、可返回、可核对的独立详情页。
- 必做：`/funds/:code` 路由；搜索/自选可进入该路由；展示全市场记录、研究补充字段、历史净值主图、窗口切换和新鲜度；明确索引外/历史缺失/质量降级状态。组合与证据入口分别留给 `v2.5`、`v2.6`。
- 验收：代码或名称检索后可进入正确详情 URL；1m/3m/6m/1y/all 窗口不覆盖旧主结论；浏览器前进/后退不丢失检索条件；桌面、平板、手机无内容遮挡。
- 不做：不以详情页触发新 live fetch，不添加评分或推荐。

### v2.5.0：Portfolio Workbench

- 目标：将现有配置持仓转为可核对的组合浏览入口。
- 必做：持仓行进入基金详情；主题/类型暴露显示可比较的权重或明确“待估值”；数据缺口和观察性问题固定呈现；保留来源与 as_of。
- 验收：估值缺失不会显示虚构收益或权重；持仓、暴露、问题三类信息可在一个页面扫描；每个基金链接只使用配置中已有代码；无调仓动作或买卖语言。
- 不做：不计算新组合风险、不建议再平衡、不写入 portfolio 配置。

### v2.6.0：News / Announcement Evidence Browser

- 目标：将既有本地 evidence 组织为可筛选、可追溯、可跳转的证据浏览器。
- 必做：按主题、来源质量、证据强度和文本筛选；相关基金代码跳转详情；来源 URL、发布时间、质量/低置信度和缺 URL 状态可见；维持 evidence-only 边界。
- 验收：筛选不改变 JSON 产物；有 URL 的证据以安全新窗口打开；低置信度、fixture、缺 URL 均不能被视觉上标为正向结论；未索引基金代码保持不可点击且有说明。
- 不做：不接入新闻/公告抓取、不用新闻生成评分或推荐。

## 风险与回滚

- UI 回滚只切回上一个 tag 并执行 `scripts/deploy_local_product_web.sh`；不删除 outputs、SQLite cache 或 scheduler。
- 若当前 JSON 缺少组合估值、新闻 URL 或基金 enrichment，页面必须保留空状态，不能由客户端推断数据。
- 若 PR CI 或本地三视口验收失败，停止该版本的发布，不合并未验收 bundle；后续版本在上一稳定 tag 基础上继续。

## 实现前一致性检查

- `AC -> task`：每个版本验收由 T01–T05 覆盖。
- `non-goal -> task`：任务不含 provider、评分、风险、配置、scheduler 或外部部署改动。
- `risk -> verification`：数据缺失、路由、响应式和回滚均有明确验证或降级路径。
- 无阻断未决问题：既有本地 API 已提供基金、组合和证据所需基础数据；若实际产物缺字段，按页面空状态处理。
