# YA FundMind OS v2.3 市场新鲜度与研究工作台实现计划

## 背景与目标

`daily ops` 已持续成功生成全市场市场情报，但指数曲线使用另一条按需的 SQLite 时序缓存路径。页面只呈现曲线的最近交易日，未呈现本次同步时间；在周末、节假日或页面缓存仍有效时，这会被误读为每日任务没有更新。

本版本解决两件事：

1. 将三条主指数的刷新纳入 AKShare daily ops 的可失败隔离步骤，保留 cache fallback 和完整数据新鲜度。
2. 将 Product Web 从“报告堆叠”改为可浏览、可核对的基金研究工作台，优先呈现市场、数据新鲜度、搜索和详细观察入口。

设计依据见 [v2.3 Research Workbench Design Lock](../design/v2.3-research-workbench-design-lock.md)。Kimi K3 作为只读设计咨询已调用；实现仍只使用项目现有 React、FastAPI、SQLite 与 Lucide/Recharts 依赖。

## 范围

- `MarketHistoryService` 支持显式强制刷新三条已允许指数，并产生结构化刷新摘要。
- 新增 `refresh-market-history` CLI；仅在 `daily ops` 的 `PROVIDER=akshare` 时调用，失败不阻塞当天其余研究产物。
- 市场历史 API 保持兼容，补充的时间语义只在既有字段上呈现，不更改 JSON response schema。
- Web 新增新鲜度呈现与“重新读取本地数据”操作，重构应用壳、市场页和共享视觉 token。
- 现有基金/组合/证据/审核页面复用新壳和通用样式，不改变数据逻辑。

## 非目标

- 不接新 provider，不改 AKShare 为默认 provider。
- 不改主评分、主风险、watchlist、portfolio、定时任务时间或真实交易边界。
- 不增加自动推荐、收益承诺、券商、LLM、MCP 或公网部署。
- 不在 UI 请求中隐式执行 live 数据抓取；手动页面刷新只重新读取本地 API/产物。

## 验收标准

- `AC-01`：`refresh-market-history --provider akshare` 对三条受限指数调用现有 provider，成功写入既有 SQLite 时序表；live 失败时维持明确的 fallback/unavailable 摘要。
- `AC-02`：`run_daily_ops.sh` 仅在 AKShare daily 环境调用预热；该步骤失败不会中断 market intelligence、daily report、dashboard 或 ops status。
- `AC-03`：市场 API payload 的 `as_of` 仍表示最近交易日，`updated_at` 与 `expires_at` 可供前端明确呈现；不把非交易日误标 stale。
- `AC-04`：市场页面可以重新读取本地数据；用户可在主图旁明确看见来源、交易日、同步时间、缓存有效期、stale/fallback。
- `AC-05`：新工作台在 1440/768/375 的截图中没有遮挡、文字裁切、无意义的卡片墙或数据状态歧义。
- `AC-06`：默认 pytest/Vitest 无真实网络依赖；Python pytest、compileall、web typecheck/test/build 均通过。

## 实现批次

### T1：市场指数预热与失败隔离

- 在 `fund_agent/market_history.py` 抽取可复用的 live 获取/标准化逻辑，增加强制刷新与批量摘要。
- 在 `fund_agent/cli.py` 新增受限的 `refresh-market-history` 命令。
- 在 `scripts/run_daily_ops.sh` 仅在 `PROVIDER=akshare` 下调用；fixture 明确跳过。
- 添加 pytest：强制刷新绕过 fresh cache、逐个指数失败隔离、缓存 fallback、CLI 输出、daily shell 合约。

### T2：时间语义与市场页面行为

- 增加通用新鲜度组件，使用既有 `as_of / updated_at / expires_at / source / stale / fallback` 字段。
- 市场页的“刷新”只重新读取本地结构化 API，展示读取时间；不在浏览器隐式网络抓取。
- 补充 Vitest 覆盖交易日与同步时间、stale/fallback、重新读取动作。

### T3：Research Workbench 视觉实现

- 依据 Design Lock 重构 `AppShell`、token、通用分区、数据带和市场主工作区。
- 保留现有 React 路由和 API 形状；其他页面获得统一壳层和表格/状态视觉，不改其研究内容。
- 以 CSS grid、稳定高度和响应式断点替代大白卡与报告式堆叠。

### T4：验证与交付

- Python 与 Web 回归；隔离本地 Web 端口用真实 outputs 做 1440/768/375 Playwright 验收。
- 在 AKShare 可用时执行一次可选 index refresh smoke；失败仅记录真实原因。
- 进行 focused diff 和对抗式审查，提交、PR、CI 后合并；不把未验收 UI 改动放入主分支。

## 执行契约

- 新鲜度的事实来源是 SQLite 与已有输出；不复制日期、不改写历史 metadata 来制造“新数据”。
- 交易日小于同步日可以是正常的非交易时段；只有缓存过期、fallback 或 provider 错误才产生相应告警。
- daily 预热使用现有 AKShare 配置（timeout/retry/quiet mode），不添加新的隐性网络依赖到默认测试。
- 市场预热是一项可失败隔离操作：没有可用数据时报告真实错误，不能伪造成功或覆盖已有正常产物。
- 新前端不读取或解析 Markdown；继续只读本地 JSON/API。
- 实现前的 `AC -> T` 映射：`AC-01/02 -> T1`，`AC-03/04 -> T1/T2`，`AC-05 -> T3/T4`，`AC-06 -> T1-T4`。

## 风险与回滚

- AKShare 可能在盘中或非交易日返回最近交易日：UI 明示语义，而不是要求日期强行等于运行日。
- 每日预热失败时，shell 继续执行且留下清晰日志；回滚只需移除该可失败步骤，不影响既有 daily pipeline。
- UI 回滚为前一版静态 bundle；不涉及缓存 schema、主评分/主风险或 scheduler 配置迁移。
