# YA FundMind OS v2.0.0-rc.1 Release Report

## 发布目标

完成 V2 M6 Release Hardening，把 v1.1-v1.5 已交付的 Artifact Catalog、Evidence/Citation、Research Copilot、只读 MCP/Skill 和本地 Console 收敛为可验证的 V2 release candidate。

PR：[#29](https://github.com/hd2yao/ya-fundmind/pull/29)。本文件随 RC 分支提交；CI、merge commit 和 tag 必须在合并门完成后成为最终发布证据。

## 本次加固

- 新增 `release-readiness`，区分 `historical_compat` 与 `post_rc`。
- daily run metadata 增加 app version、git commit、dirty 和 trigger provenance。
- Final `v2.0.0` 不能用 pre-RC 历史 run 放行。
- V1/V2 旧 schema、未知字段、缺字段和不改写矩阵完成。
- Query/Evidence/Copilot/MCP 输出统一敏感字段与本地路径脱敏。
- Research/MCP audit 使用 no-follow append，symlink 越界失败关闭。
- 中英文、插空和收益承诺绕过被 guardrail 拒绝；不安全 optional renderer 回退 deterministic renderer。
- strict contract 拒绝未知 schema、旧 snapshot 和无效生成时间作为发布证据。
- AKShare 主线程 timeout 改为可中断 deadline；失败仍保留 trace/cache fallback 语义。
- CI 覆盖 Python 3.10/3.12，默认 pytest 由 socket guard 保证离线。
- 增加 100 artifact 性能预算和六类 topic CLI/MCP/Web 端到端矩阵。

## RC 与 Final 门

RC 可以使用历史真实 run 证明 V1/V2 兼容，但不把它们计为 Final 观察。RC 合并并安装后，必须由 scheduler 在三个不同日期生成满足以下条件的 run：

- `app_version=2.0.0rc1`
- `git_commit=<RC merge commit>`
- `git_dirty=false`
- `trigger=daily_ops/launchd/scheduler`
- AKShare live rows > 0，无 fallback、critical、degraded
- strict report/snapshot/trace contract 通过

达到 `post_rc status=pass`、P0/P1=0 后，才创建独立 Final PR 和 `v2.0.0` tag。

## 边界

- 没有修改主评分或主风险。
- 没有改变 daily provider 默认、watchlist、portfolio 或 scheduler schedule。
- 没有新增自动推荐、交易、券商、收益承诺、SaaS 或公网服务。
- Research Copilot 只读本地白名单 JSON；LLM/MCP/Web 都不阻塞 V1 daily/weekly。
