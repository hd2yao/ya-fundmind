# YA FundMind OS v2.3 Research Workbench Design Lock

## 设计决定

本次不把现有报告页面换一套颜色，而是把本地 Product Web 收敛为一个以数据浏览为先的「Fund Research Desk」。它服务于个人基金/ETF 的研究观察：先辨认市场与数据状态，再浏览基金、板块、组合和证据。它不是交易终端、营销落地页，也不产生买卖建议。

Kimi K3 设计咨询的可采纳部分是“投研底稿 / Research Desk”：用稳定的数据排版、紧凑的数据带、时序主图区和一致的空/错误状态替代堆叠报告卡。其建议的米白主色不采用，避免界面落入单一米色调；项目保持高对比浅石墨纸面、墨绿骨架和矿物青绿强调色。

## 任务模型

- 用户场景：每天运行后，在本机打开页面查看市场、搜索基金并进入已有研究产物。
- 主要任务：在首屏判断数据是否已同步、交易日是哪天、市场发生了什么，再进入具体基金或板块。
- 主操作：切换指数/时间窗口，搜索基金，打开板块或主题详情，重新读取本地结构化产物。
- 次操作：查看来源、新鲜度、数据质量、证据和人工审核状态。
- 非目标：交易下单、收益预测、推荐、由页面发起隐式 live provider 请求。

## 信息模型

### 必须显示

1. 当前研究工作区和全局基金搜索。
2. 市场交易日（`as_of`）、本次同步时间（`updated_at`）、缓存失效时间（`expires_at`）、`source`，以及 `stale` / `fallback` 状态。
3. 主要指数的数值、日涨跌、曲线、样本数和可切换时间窗口。
4. 行业板块目录、主题观察和可进入详情的动作。
5. 研究边界：仅作研究观察，不自动交易、不构成买卖建议。

### 状态与边界

- loading / empty / error / stale / fallback / normal 都有清晰、非阻塞的呈现。
- 基金名称超出表格列时截断，标题属性保留全称；数字列不可因内容变化抖动。
- `as_of` 是行情交易日，不能被标成“页面更新时间”。`updated_at` 是本地成功同步时刻，二者必须同时出现。
- 非交易日允许交易日早于同步日；只有 `stale=true` 或 `fallback_used=true` 才呈现告警。

## 布局模型

桌面阅读顺序：

```text
[左侧：产品识别 / 主导航 / 本地研究边界]
[顶部：当前工作区 | 全局基金搜索 | 最新同步状态]
[市场脉冲条：交易日 / 同步时刻 / 数据覆盖 / 质量]
[主工作区：指数选择与主图(2/3) | 当前指数数据与新鲜度(1/3)]
[下层：行业板块可筛选目录(2/3) | 主题、趋势、质量观察(1/3)]
[深层：展开数据表 / 证据抽屉 / 研究边界]
```

- 1440px：固定 248px 左侧资料栏；正文最大宽度 1720px；主图采用 2:1 的稳定栅格。
- 768px：侧栏变为抽屉，主区改为单列，指标带横向滚动但不隐藏数据质量。
- 375px：顶部只保留菜单、搜索入口和同步状态；指数与范围按钮为可换行的分段控制；表格保留横向滚动和首列可读。
- 任何固定格式区域（图、按钮、数据带、表格）均使用稳定高度/宽度约束，避免异步加载导致跳动。

## 风格模型

- 风格名：**Fund Research Desk（基金研究台）**。
- 情绪关键词：安静、可靠、可核对、专业、非交易刺激。
- 色彩：深墨绿 `#102B28` 做骨架；矿物青绿 `#0E8B7E` 做唯一主要强调；碳黑 `#18231F` 做文字；雾白 `#F4F6F3` 做画布；暖灰/石灰做分隔；涨跌仅使用受控的正负语义色。
- 字体：系统中文字体优先，数字使用 `ui-monospace` / `SFMono-Regular` 回退；标题紧凑但不是营销级大字。
- 圆角/阴影：4px 到 10px，小圆角；以分隔线、浅层次和微弱阴影建立结构，避免浮动卡片墙。
- 图标：仅 Lucide；图标按钮都有可访问名称和 tooltip。
- 动效：仅用于加载、抽屉和状态切换，120–180ms；不得移动或遮挡核心内容。
- 不可破坏：数据源与新鲜度永远高于装饰；白底正文不能因任何色彩/背景降低对比度。

## 组件规则

| 组件 | 规则 |
| --- | --- |
| `DataFreshnessStrip` | 固定展示交易日、同步、缓存有效期和来源；stale/fallback 改为有文字的状态条，不只靠颜色。 |
| `MarketIndexWorkspace` | 左侧/上方为指数与窗口选择，主图占视觉权重；右侧/下方为数值和数据契约元信息。 |
| `MetricRail` | 使用连续的数据带而非四个独立大卡；每项有标签、值、说明。 |
| `DataTable` | 统一表头、行高、数字右对齐、透明 hover；密集数据不再套第二层卡。 |
| `StatusBadge` | 只表示 data quality / stale / fallback 等状态；不承担主视觉。 |
| `StatePanel` | 加载、空、错误保持同一个结构与最小高度，错误解释下一步但不制造假数据。 |

## 页面复用策略

- 基金页：全市场筛选表为主，基金详情为固定指标带 + 历史主图 + 标签区；来源与新鲜度复用 `DataFreshnessStrip`。
- 组合页：组合快照 + 暴露/缺口双栏；把“当前估值不可用”留在数据位，而不是显示误导性 0。
- 证据页：按来源质量与主题过滤的证据流；低置信度和缺 URL 必须可见。
- 审核页：队列优先，操作集中到每行右侧；不把审核表单包装成营销卡。
- 报告页：仅作为本地产物目录，不抢占数据浏览入口。

## 验收清单

- [ ] 页面首屏可同时看见“交易日”和“本次同步”，并不把非交易日误判为 stale。
- [ ] stale 或 fallback 时以文字和图标说明原因，屏幕阅读器可读。
- [ ] 市场页在桌面、平板和手机没有重叠、横向溢出或被裁切的文字；表格区域除外且有显式横向滚动容器。
- [ ] 指数、板块、主题和基金搜索的主操作均可用键盘完成。
- [ ] 不存在营销 hero、装饰性渐变/光球、嵌套卡片或以大段报告替代数据浏览。
- [ ] 现有路由、API response、研究边界和数据质量语义保持兼容。
- [ ] Playwright 在 1440/768/375 完成截图与关键交互验收。
