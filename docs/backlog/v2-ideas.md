# V2 Ideas

本文件记录 V2 方向。这里的内容不阻塞 V1，也不应该混入 V1 Milestone。

## V2 原则

- V2 可以探索智能化和产品化，但必须建立在 V1 稳定输出契约之上。
- V2 下游应读取 JSON report、provider trace、snapshot、dashboard artifact，不应解析 Markdown。
- 任何自动化解释、推荐或交易方向都必须另行定义安全边界和审批流程。
- V2 不应反向要求 V1 改变核心交付范围。

## 投资博主 Skill

把不同投资博主或研究流派整理为 Skill，用于解释框架对照和人工阅读辅助。

V1 不做原因：

- 容易引入主观风格和不稳定结论。
- 需要 LLM/Skill 运行边界。
- 不影响 V1 本地研究台交付。

## Agent 问答

基于本地 JSON artifact 做问答，例如“今天半导体主题为什么热”、“某只基金缺哪些数据”。

V1 不做原因：

- 需要 Agent 会话、检索、权限和回答约束。
- 当前优先级是稳定产物和 dashboard。

## MCP

为外部工具暴露本地投研数据。

V1 不做原因：

- 需要接口设计、权限和兼容性承诺。
- V1 先冻结文件契约。

## LangGraph

使用图编排 Agent/研究流程。

V1 不做原因：

- 当前本地 CLI 和 scripts 已能覆盖 daily/weekly 自动化。
- 引入编排框架会增加调试和维护成本。

## LLM 自动解释

自动把市场、基金、组合和新闻证据解释成自然语言。

V1 不做原因：

- 需要防止幻觉、过度结论和买卖建议。
- 需要引用约束和人工审核策略。

## 自动推荐

根据评分或信号自动给出推荐列表。

V1 不做原因：

- 当前系统只做研究辅助和观察。
- 推荐容易被理解为投资建议，需要更严格合规边界。

## 自动交易

自动下单、调仓或止盈止损。

V1 不做原因：

- 明确越过 V1 边界。
- 需要券商接口、风控、审计、权限、合规和失败处理。

## 券商接入

读取真实账户或下单。

V1 不做原因：

- 涉及敏感凭证和真实资金。
- V1 只读本地配置，不接券商。

## SaaS

多用户云端服务。

V1 不做原因：

- 需要账号、权限、数据隔离、部署、安全和成本治理。
- 当前定位是本地个人工作台。

## 移动端

原生 App 或移动端适配。

V1 不做原因：

- 需要额外 UI/交互和发布链路。
- V1 先做好本地 dashboard。

## 小程序

微信/支付宝等小程序版本。

V1 不做原因：

- 需要平台审核、账号体系和后端服务。
- 不影响 V1 本地交付。
